# C1 - Dispatcher and roles support Codex workers

## Goal

Szef can start a Codex reviewer or implementer with `mowa-dispatch-herdr
<name> <role> <ticket> codex` and it behaves like a Claude worker: reads the
role, follows `_common.md`, writes notes.

## Workspace

Launcher scripts and roles are Szef-owned (`AGENT-LOOP.md`). No product code.
Files: `scripts/agents/mowa-dispatch-herdr` (symlinked from
`/home/szymon/bin`), `roles/_common.md`.

## What is already known

- `herdr agent start --kind codex` is supported; the old script started Codex
  with no flags, so it would sit in an approval prompt nobody answers.
- Codex reads `AGENTS.md` from cwd. `.claude/settings.json` hooks never run
  for Codex, so role context must go into the workspace `AGENTS.md`.
- `codex exec --skip-git-repo-check -s workspace-write --add-dir
  /home/szymon/mowa -c sandbox_workspace_write.network_access=true` was
  verified on 2026-09-12: it read `roles/reviewer.md`, touched and removed a
  file under `specs/`, and got `HTTP/2 200` from example.com. Model: GPT-6.
- The interactive TUI takes `-a never`; `codex exec` does not (it never asks).

## Done when

- Dispatcher starts Codex with approval `never`, sandbox `workspace-write`,
  `--add-dir /home/szymon/mowa`, network on, reasoning effort from
  `MOWA_EFFORT`, optional `MOWA_CODEX_MODEL`.
- Workspace `AGENTS.md` for a Codex worker ends with the role text
  (`_common.md` + `roles/<role>.md`).
- `roles/_common.md` tells a Codex session what to do instead of
  `EnterWorktree`.

## Scope edge

No change to Claude dispatch. No change to ticket or notes shape.

## Evidence bar

Diff of the script and role file, plus one live Codex dispatch (C2).

## Deliverable

Append handoff to `specs/codex-workers/notes.md`, then stop.
