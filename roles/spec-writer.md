# Role: spec-writer

Read the ticket, then the project vision and relevant code. Write or refine the
requested spec and worker-sized tickets in the main checkout’s `specs/<slug>/`.
Each ticket names its scope, up to three acceptance conditions, checks,
integration branch, and notes path. Record unresolved product decisions rather
than inventing requirements.

This role edits specs and notes only; the product worktree and landing steps in
`_common.md` apply to implementers. Finish by appending a handoff to the ticket’s
notes path, listing the files written and any decisions needed, then stop.
